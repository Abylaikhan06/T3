# Project T3

Это мой проект по аутентификации и авторизации пользователей.

Я сделал сайт, где пользователь может зарегистрироваться, войти в аккаунт,
изменить свои данные, удалить аккаунт и работать с заказами. Также есть
администратор, который может менять права доступа для разных ролей.

## Что есть в проекте

- регистрация и вход пользователя;
- выход из аккаунта;
- JWT-токен для авторизации;
- пароль хранится в виде hash через `bcrypt`;
- мягкое удаление аккаунта: пользователь остается в базе, но больше не может войти;
- три роли: `admin`, `manager`, `user`;
- проверка доступа к заказам;
- админ-панель для изменения правил;
- обычный сайт и Swagger для проверки API;
- PostgreSQL для хранения данных.

## Как запустить

Сначала нужно создать пользователя и базу в PostgreSQL:

```sql
CREATE USER t3_user WITH PASSWORD 't3_password';
CREATE DATABASE t3_auth OWNER t3_user;
```

Потом в папке проекта выполнить команды:

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
copy .env.example .env
uvicorn main:app --reload
```

Перед запуском нужно открыть `.env` и указать свои значения для подключения к
базе и секретного ключа JWT.

Обычный сайт:

```text
http://127.0.0.1:8000/
```

Swagger API:

```text
http://127.0.0.1:8000/docs
```

## Тестовые аккаунты

Если в `.env` включено `SEED_DATA=true`, при запуске создаются тестовые
пользователи:

| Роль | Email | Пароль |
| --- | --- | --- |
| Администратор | `admin@example.com` | значение `ADMIN_PASSWORD` из `.env` |
| Менеджер | `manager@example.com` | значение `MANAGER_PASSWORD` из `.env` |
| Пользователь | `user@example.com` | значение `USER_PASSWORD` из `.env` |

В моем локальном запуске для администратора используется:

```text
admin@example.com
Admin123!
```

## Как работают роли

`admin` может видеть все заказы и менять правила доступа.

`manager` может видеть и изменять все заказы, но не может управлять правилами.

`user` может создавать заказы и работать только со своими заказами.

Если пользователь не вошел в аккаунт, сервер возвращает ошибку `401`. Если
пользователь вошел, но ему нельзя выполнить действие, возвращается `403`.

## Таблицы базы данных

В проекте используются такие таблицы:

| Таблица | Для чего нужна |
| --- | --- |
| `users` | Данные пользователей, пароль и статус аккаунта |
| `sessions` | Активные и закрытые JWT-сессии |
| `roles` | Список ролей |
| `user_roles` | Какая роль у пользователя |
| `business_elements` | Ресурсы приложения, например заказы |
| `access_role_rules` | Какие действия разрешены каждой роли |

В правилах есть доступ для своих объектов и доступ для всех объектов.
Например, обычный пользователь может изменять свой заказ, а администратор
может изменять любой заказ.

## Структура папок

```text
main.py                 запуск приложения
app/
  application.py        подключение FastAPI и роутеров
  config.py             настройки из .env
  database.py           подключение к базе
  models.py             таблицы базы
  schemas.py            данные запросов и ответов
  validators.py         проверки ввода
  security.py           пароли и JWT
  dependencies.py       проверка текущего пользователя
  services.py           роли, права и начальные данные
  routers/              маршруты API
static/                 страницы сайта, стили и JavaScript
tests/                  тесты
```

## Проверка тестов

```powershell
.\.venv\Scripts\python.exe -m pytest -q
```

Тесты проверяют регистрацию, вход, удаление аккаунта, права ролей, работу
администратора, валидацию данных и открытие сайта.
